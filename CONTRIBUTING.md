# Contributing

Thank you for contributing to Vane Enterprise LLC projects. We value professionalism, security, and constructive collaboration.

## Contribution Standards

- Keep changes focused and easy to review.
- Follow existing repository conventions and patterns.
- Add or update tests for behavior changes.
- Avoid committing secrets, credentials, or sensitive operational data.
- Document significant changes when relevant.

## Workflow

1. Create a short-lived feature branch from the relevant base branch.
2. Make the smallest valid change that addresses the task.
3. Run the repo’s validation checks and tests before opening a PR.
4. Open a pull request with a clear summary and validation details.
5. Address review feedback and finalize the change.

## Pull Request Expectations

A pull request should include:

- summary of the change
- business or technical justification
- validation performed
- any security or compatibility considerations

## Code Quality

- Prefer readable and maintainable code.
- Follow project naming and formatting conventions.
- Avoid unnecessary dependencies or scope creep.

## Security

- Never commit personal data, credentials, or plaintext secrets.
- Report vulnerabilities privately through the official security reporting path.
- If in doubt, ask before making a change that affects security boundaries.

## Review Policy

All changes should be reviewed by a qualified maintainer or approver. Security-sensitive changes require higher scrutiny and explicit authorization when necessary.

## Behavior Expectations

Contributors are expected to participate professionally, respect reviewers, and keep discussions focused on deliverables and technical evidence.
